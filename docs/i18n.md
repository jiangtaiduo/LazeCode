# Internationalization (i18n)

[English](i18n.md) | [Simplified Chinese](i18n.zh-CN.md)

The native UI has two languages: English and Simplified Chinese. There is no
JSON dictionary or runtime key lookup; strings live at their call site and are
selected by the active `Language`.

## Sources of truth

| Location | Responsibility |
|---|---|
| `lazecode-core::settings::Language` | persisted setting (`english` / `chinese`) |
| `lazecode-ui::i18n::t` | `(lang, en, zh)` selector |
| `crates/lazecode-ui/src/*` | all UI strings, usually via `tr!` |
| `crates/lazecode-app/src/main.rs` | native macOS menu labels via `pick(zh, en, cn)` |
| `lazecode-core` toasts/models | dynamic messages that need both languages |

## Usage

```rust
crate::tr!(model, "Save", "保存")
```

`tr!` expands to `lazecode_ui::i18n::t(model.settings.language, en, zh)`.
Use it at render time; do not cache a translated `&str` in a struct that
outlives a language switch.

Dynamic strings are formatted at the call site:

```rust
if model.settings.language.is_zh() {
    format!("已打开 {name}")
} else {
    format!("Opened {name}")
}
```

## Adding or changing text

1. Add the English and Chinese strings together; never add one side only.
2. Use `tr!` for static UI text and `language.is_zh()` for formatted messages.
3. Update the native menu label in `pick(zh, en, cn)` if the action is also in
   the menu.
4. Keep keyboard shortcut glyphs (`⌘`, `⇧`) identical in both languages.

## Native menu

The macOS menu is built before the first frame, so it cannot read a UI
dictionary. `main.rs` calls `pick(zh, ...)` and rebuilds the menu when the
language changes. The menu therefore stays a second mirror; keep it in sync
with the corresponding toolbar/palette labels.

## Checks

`cargo test --workspace` covers localized model/UI helper behavior. There is no
separate i18n linter because there is no key set to drift; review must confirm
that both branches of every new `tr!` / `is_zh()` call are present.
